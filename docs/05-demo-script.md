# 05. Сценарий защиты

Семь минут, из которых пять — показ работающего решения. Всё, что здесь
описано, выполняется из репозитория; заранее собранные колоды нужны только
как запасной план и чтобы не ждать модель на сцене.

## Подготовка (за 15 минут до выхода)

```bash
backend/.venv/Scripts/python.exe -m uvicorn sd.api:app --port 8021
```

```bash
npm run dev --prefix frontend -- --port 5175
```

Чек-лист:

- [ ] `http://127.0.0.1:8021/api/status` отвечает: в `renderers` есть
      `powerpoint`, в `llm` — модель, в `skills` — версии промптов
- [ ] Ollama запущена, `ollama ps` показывает `qwen3:4b-instruct`
- [ ] в библиотеке (вкладка «Свои») загружен шаблон организаторов — VK Tech
      или VK Education; при загрузке отрисовались обложки
- [ ] заранее собрана колода на демо-контенте (`data/content/product`) —
      она лежит в «Недавних», все три варианта с pdf и html
- [ ] прогнан `sd matrix data/content/product` — `data/out/matrix/index.html`
      открыт в отдельной вкладке
- [ ] если модели нет или сеть ненадёжна — переключатель «Выключить модель»:
      план строится эвристикой, контекстуальный аудит помечается пропущенным

## Ход показа

**0:00 — Проблема одной фразой.** «Генеративный ИИ уже пишет содержание. Он не
умеет другого: сверстать это в фирменном шаблоне компании. Gamma и Copilot
делают слайды в своих темах — чужой шаблон они не разбирают. Мы разбираем».

**0:30 — Шаблон, который сервис видит впервые.** Загрузить шаблон жюри через
«Загрузить шаблон» (или показать загруженный VK-шаблон), нажать на карточку —
предпросмотр макетов. Назвать три шага: дизайн-система → библиотека
паттернов → вёрстка. «В коде генерации нет ни одного HEX-цвета и ни одного
названия шрифта — это проверяется тестом, который обходит синтаксическое
дерево».

**1:15 — Запуск сборки.** Ввести тему или прикрепить файл контента, «Собрать
структуру» → проверить план → «Создать слайды». Сборка трёх вариантов с
моделью идёт 2–3 минуты — **её запускаем сейчас, а рассказываем на заранее
собранной колоде** из «Недавних».

**1:45 — Три варианта.** Переключатель в шапке: сжато 12 · сбалансированно
14 · просторно 15. «Один план истории, модель спрошена один раз; варианты —
это плотность: сколько мыслей на слайд, разделители, выбор макетов. Просторный
не разрастается больше полутора длин и потолка ТЗ в 15 слайдов — иначе это другая презентация».

**2:30 — Слайды.** Пролистать: обложка на макете обложки, цифры с подписями,
таблица и график — нативные объекты. Под слайдом — объяснение выбора макета:
«архетип 1.00 · ёмкость 0.93 · плотность». Скачать `.pptx`, **открыть в
PowerPoint**: текст в плейсхолдерах, всё правится руками.

**3:30 — Аудит.** Кнопка «Аудит»: 28 проверок по Приложению 1, находки по
группам. Показать разделение: детерминированные (границы, поля, шкала кеглей,
цифры не из исходника — «модель написала 0,5 дня, в источнике 1 день, аудит
поймал») и контекстуальные (вопросы модели: вывод ли в заголовке, связаны ли
соседи — помечены отдельно, на повторе могут ответить иначе). Отметить
исправимые находки → «Исправить выбранное»: пересобираются только эти слайды,
на макете с большим числом мест или ужатым бюджетом.

**4:45 — Экспорт.** PDF — той же кнопкой; «Поделиться» — ссылка на страницу
варианта, открыть в новой вкладке: кадры и текст слайдов, листается стрелками.

**5:15 — Доказательство адаптивности.** Вкладка с матрицей: один и тот же план
на шести шаблонах, под один и тот же слайд выбираются разные макеты — на
Pitchbook цифры уходят в `metrics`, на фотоальбоме в `gallery`, потому что
других макетов там нет.

**6:00 — Колода жюри готова.** Вернуться к запущенной сборке: три варианта,
аудит, скачать. «Разбор — секунды, сборка с моделью — минуты, против часов
ручной вёрстки».

**6:45 — Чем закрываем кейс.** Парсинг OOXML → дизайн-система → зрение по
рендеру → модель для смысла (открытые веса, 4B, на ноутбуке) →
детерминированная вёрстка → аудит с выбором, что чинить → `.pptx` / `.pdf` /
`.html`. Промпты — отдельными версионированными файлами. Open source, без
Docker, запускается двумя командами.

## Если что-то пойдёт не так

| Симптом | Что делать |
|---|---|
| Модель не отвечает или медленная | «Выключить модель»: план эвристикой, вёрстка от модели не зависит; контекстуальный аудит будет помечен пропущенным — это честный результат, а не поломка |
| Бюджет времени модели исчерпан на третьем варианте | Так и задумано: в карточке варианта видно «пропущено: бюджет исчерпан», остальное собрано |
| Нет PowerPoint на машине | Рендер и PDF отключатся сами; показать заранее собранную колоду и матрицу |
| Шаблон жюри разобрался плохо | Показать отчёт: сервис пишет, чего не нашёл (`в шаблоне не нашлось паттернов под архетипы…`), и берёт ближайшие по структуре |
| Ремонт не помог | Панель скажет почему: «в шаблоне нет макета на N мест — фрагмент остаётся неразмещённым» |

## Вопросы, которые зададут

**«Где здесь ИИ, если вёрстка детерминированная?»** Модель отвечает за смысл:
структуру истории, заголовки-выводы, формулировки нужной длины и контекстуальный
аудит. Вёрстка намеренно не на модели — иначе результат нельзя проверить и
повторить. Зрение работает по рендеру: препятствия, безопасная зона,
переполнения, фактический контраст.

**«Как докажете, что не зашито под эти шаблоны?»** Провенанс у каждого
значения дизайн-системы; тест, запрещающий цвета и шрифты в коде генерации;
матрица «один контент × N шаблонов»; шаблон жюри прямо на защите.

**«Почему модель такая маленькая?»** ТЗ разрешает только открытые веса до
35B. 4B на ноутбуке укладывается в бюджет времени и не требует стенда; в
`.env` меняются три строки — и работает Qwen3-32B или API организаторов.
Страховки от слабостей маленькой модели описаны в `MODELS.md`: проверка плана
на выдумку, вычистка выдуманных контактов, сверка цифр с исходником.

**«Что, если контент не влезает?»** Лестница: кегль вниз по шкале шаблона →
сократить моделью → срезать хвост списка → обрезать по словам → оставить слот
пустым и записать фрагмент в «не размещено» — он попадёт в аудит как находка
с кнопкой «исправить».

**«Что с чужим шрифтом, которого нет на машине?»** Метрики берём из файла
шрифта, если он вшит в pptx; иначе подставляем метрически совместимый
(Calibri → Carlito, Cambria → Caladea) и пишем это в отчёт.

**«Сколько это занимает?»** Разбор шаблона — секунды; один вариант без
модели — 15–50 с; три варианта с моделью и полным аудитом — 2–3 минуты, в
пятиминутный лимит ТЗ укладывается с запасом.
