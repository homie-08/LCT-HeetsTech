# 10. HTTP API

Интерфейс и CLI работают поверх одного ядра, и всё, что умеет интерфейс,
доступно по HTTP. Сервер поднимается одной командой (`run.cmd` или
`run.sh`), после чего:

- интерактивная документация — <http://127.0.0.1:8021/docs> (Swagger UI,
  FastAPI собирает её сам из моделей);
- схема — <http://127.0.0.1:8021/openapi.json>;
- сам интерфейс — <http://127.0.0.1:8021/>.

Длинные операции устроены одинаково: запрос создаёт задание и сразу
возвращает его `id`, а состояние читается опросом. В ответе задания есть
`status` (`queued` · `running` · `ready` · `failed`) и `stage` — человеческая
строка вроде «вариант «Сбалансированно»: план, макеты, сборка».

## Состояние сервиса

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/health` | жив ли сервер |
| `GET` | `/api/status` | модель, доступные рендереры, версии промптов |

```bash
curl http://127.0.0.1:8021/api/status
# {"llm":"LLM: openai_compatible / qwen3:4b-instruct",
#  "renderers":["powerpoint"],
#  "skills":{"planner":5,"writer":2,"shortener":2,"auditor":2}}
```

## Шаблоны

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/templates` | загрузить шаблон `.pptx` / `.potx` и разобрать его |
| `GET` | `/api/templates/{id}` | состояние разбора: дизайн-система, паттерны, замечания |
| `GET` | `/api/templates/{id}/preview/{pattern}` | рендер паттерна со слотами |
| `GET` | `/api/library` | библиотека: встроенные стили, свои шаблоны, обложки |
| `POST` | `/api/library/upload` | добавить свой шаблон в библиотеку |

```bash
curl -F "file=@шаблон.pptx" http://127.0.0.1:8021/api/templates
# {"id":"24c0f8b487e7","status":"queued"}
curl http://127.0.0.1:8021/api/templates/24c0f8b487e7
```

## Структура и сборка

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/outline` | структура будущей колоды по тексту: состав слайдов, заголовки-выводы, тезисы |
| `POST` | `/api/decks` | собрать колоду: три варианта вёрстки на разобранном шаблоне |
| `POST` | `/api/decks/html` | то же для HTML-шаблонов дизайнерского пакета |
| `GET` | `/api/decks/{id}` | состояние задания: слайды, метрики, находки аудита, ссылки на файлы |
| `DELETE` | `/api/decks/{id}` | удалить проект вместе с файлами |

```bash
# структура до вёрстки — синхронно, без рендера
curl -F "text=Итоги квартала: сроки, отток, план" -F "slides=10" \
     http://127.0.0.1:8021/api/outline

# сборка: шаблон + контент-пакет файлами
curl -F "template_id=24c0f8b487e7" -F "brief=Итоги квартала" -F "slides=12" \
     -F "files=@product.md" -F "files=@dynamics.csv" \
     http://127.0.0.1:8021/api/decks
# {"id":"f8921b680e67","status":"queued"}
```

В ответе `GET /api/decks/{id}` лежит массив `variants[]` — по одному на
вариант вёрстки (`compact`, `balanced`, `spacious`), и у каждого: карточки
слайдов с объяснением выбора макета, метрики нормоконтроля, находки аудита
(`defects`), список выполненных и пропущенных проверок, ссылки на файлы.

## Аудит и ремонт

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/decks/{id}/repair` | пересобрать слайды выбранных находок |

```bash
curl -F "variant=balanced" -F "defects=8:coverage:81888,10:overflow:13237" \
     http://127.0.0.1:8021/api/decks/f8921b680e67/repair
# {"id":"f8921b680e67","status":"running","slides":[8,10]}
```

Чинятся только находки с признаком `fixable`; по остальным сборке нечего
менять — они про шаблон или про смысл. Подробно — [`AUDIT.md`](../AUDIT.md).

## Файлы

| Метод | Путь | Что отдаёт |
|---|---|---|
| `GET` | `/api/decks/{id}/file?variant=balanced` | `.pptx` варианта |
| `GET` | `/api/decks/{id}/pdf?variant=balanced` | `.pdf` варианта |
| `GET` | `/api/decks/{id}/html?variant=balanced` | самодостаточную страницу колоды |
| `GET` | `/api/decks/{id}/slide/{variant}/{n}` | картинку слайда (рендер) |

## Демо-режим

Для показа без загрузки файлов: `GET /api/demo` отдаёт список готовых
шаблонов и контент-пакетов, `POST /api/demo/template` разбирает выбранный
шаблон, `POST /api/demo/deck` собирает колоду на демо-контенте. Этим же
пользуется скрипт записи видео — [`08-video.md`](08-video.md).
