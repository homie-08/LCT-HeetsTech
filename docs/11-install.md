# 11. Локальный запуск

Инструкция написана не по памяти: репозиторий склонирован в пустую папку и
пройден с нуля так, как это сделает эксперт. Два места, где прогон спотыкался,
уже починены (`run.cmd` рвал русские строки, `npm install --prefix` ставил
зависимости не туда) — ниже описано состояние после починки.

Сервис рассчитан на запуск на машине пользователя: ему нужен рендерер
(PowerPoint или LibreOffice) и модель — поэтому общего хостинга у нас нет,
а есть воспроизводимый запуск одной командой.

## Что нужно заранее

| Компонент | Версия | Зачем | Без него |
|---|---|---|---|
| Python | 3.11 (вызов `py -3.11` на Windows, `python3.11` на Linux/macOS) | бэкенд и CLI | не запустится |
| Node.js | 18+ (`npm` в PATH) | сборка веб-интерфейса | поднимется только API и Swagger |
| PowerPoint **или** LibreOffice | любой современный | рендер слайдов для визуальных проверок и экспорт PDF | сборка идёт, визуальный аудит и PDF отключаются |
| Модель с открытыми весами | OpenAI-совместимый endpoint | план истории и тексты | сборка идёт на эвристиках — молча, без ошибок |

Дисковое место: ~700 МБ на окружение Python и `node_modules`, плюс кеш рендера
в `data/`. Сеть нужна только на первую установку зависимостей.

## Запуск

```bash
git clone https://github.com/homie-08/LCT-HeetsTech.git
cd LCT-HeetsTech
run.cmd
```

На macOS/Linux — `./run.sh`. Порт задаётся аргументом: `run.cmd 8025`,
по умолчанию 8021.

Скрипт делает четыре шага и печатает каждый: создаёт `backend/.venv`, ставит
зависимости бэкенда, собирает фронтенд, поднимает сервер. Повторный запуск
пропускает готовые шаги.

Сколько это занимает на нашей машине (Windows 11, SSD):

| Шаг | Время |
|---|---|
| Клонирование | ~1 мин 20 с (в репозитории лежат записи прогона) |
| Первый `run.cmd` — окружение, зависимости, сборка интерфейса | ~4 мин |
| Последующие запуски | ~50 с (пересборка фронтенда) |

## Проверка, что всё поднялось

```bash
curl http://127.0.0.1:8021/api/status
```

Ответ показывает, что сервис нашёл сам:

```json
{"llm":"LLM: openai_compatible / qwen3:4b-instruct",
 "renderers":["powerpoint"],
 "skills":{"planner":5,"writer":2,"auditor":2,"shortener":2,"shortener-batch":2}}
```

- `renderers` пустой — рендерер не найден, визуальные проверки и PDF выключены;
- после `openai_compatible /` пусто — не заполнен `SD_LLM_MODEL`, планирование
  пойдёт на эвристиках.

Дальше:

- веб-интерфейс — <http://127.0.0.1:8021/>;
- Swagger — <http://127.0.0.1:8021/docs>, описание эндпоинтов с примерами
  в [`10-api.md`](10-api.md);
- кнопка **«Демо»** в интерфейсе собирает колоду на готовом шаблоне и контенте —
  самый быстрый способ увидеть весь путь целиком.

Без интерфейса, из командной строки:

```bash
backend/.venv/Scripts/python.exe -m sd build "ресурсы/Датасет/Шаблон презентации VK Education.pptx" data/content/product --out data/out/deck.pptx
```

## Модель

Файл `.env` создаётся из `.env.example` при первом запуске; пока `SD_LLM_MODEL`
пуст, сервис работает без модели. Мы гоняли на локальной Ollama:

```bash
ollama pull qwen3:4b-instruct
```

```ini
SD_LLM_PROVIDER=openai_compatible
SD_LLM_BASE_URL=http://127.0.0.1:11434/v1
SD_LLM_MODEL=qwen3:4b-instruct
SD_LLM_BUDGET_S=150
```

Подойдёт любой OpenAI-совместимый endpoint — vLLM, Inference API организаторов.
ТЗ ограничивает открытыми весами до 35B; какие модели проверяли и сколько им
нужно памяти — в [`../MODELS.md`](../MODELS.md). После правки `.env` сервер
нужно перезапустить.

Вариант без сети совсем:

```ini
SD_LLM_PROVIDER=stub
```

## Если что-то пошло не так

**`py` не найдена (Windows).** Установщик python.org ставит лаунчер `py`;
из Microsoft Store он не всегда попадает в PATH. Проверка — `py -3.11 -V`.

**`npm` не найден.** Шаг «[3/4] Фронтенд» падает, API при этом рабочий:
поднимите сервер напрямую и пользуйтесь Swagger —
`backend/.venv/Scripts/python.exe -m uvicorn sd.api:app --port 8021`.

**Порт занят.** `run.cmd 8025` — и интерфейс переедет туда же.

**В `renderers` пусто.** Сборка `.pptx` работает, выключаются визуальные
проверки и экспорт PDF. Достаточно поставить LibreOffice — он ищется по
стандартным путям, настраивать ничего не нужно.

**Сборка идёт, но слайды выглядят «эвристично».** Почти всегда это пустой
`SD_LLM_MODEL` или недоступный `SD_LLM_BASE_URL`: сервис намеренно не падает
из-за модели, а достраивает план сам. Смотрите поле `llm` в `/api/status`.

**Модель не укладывается в бюджет.** `SD_LLM_BUDGET_S` — сколько секунд одной
сборке разрешено тратить на модель; по исчерпании сборка продолжается без неё.
На 4B-модели и слабой видеокарте колода из восьми слайдов занимает около
шести минут — это мера железа, а не сервиса.

## Тесты

```bash
backend/.venv/Scripts/python.exe -m pytest backend -q
```

```bash
cd frontend && npm test
```

Часть тестов бэкенда рендерит слайды через PowerPoint COM и конфликтует с
сервером, если тот в это же время собирает колоду, — запускайте на простое.
